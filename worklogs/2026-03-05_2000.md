# 작업 일지 - 2026-03-05 20:00

## 작업 내용: Prometheus 메트릭 스크래핑 실패 해결 (바인딩 주소 수정)

### 배경

baremetal 클러스터에서 Alertmanager에 `TargetDown`, `etcdMembersDown`, `etcdInsufficientMembers` 알럿이 활성화됨. 쿠버네티스 자체는 정상이나 kube-proxy, kube-controller-manager, kube-scheduler, etcd의 메트릭 엔드포인트가 `127.0.0.1`에 바인딩되어 Prometheus Pod에서 접근 불가.

### 수정 내역

#### 1. kube-controller-manager / kube-scheduler (`--bind-address`)

- **파일**: `kubernetes/roles/config-kube-scheduler-and-controller/tasks/main.yaml`
- **변경**: `--address=127.0.0.1` → `--bind-address=0.0.0.0` (regexp/replace 수정)
- **이유**: `--address` 플래그는 K8s 1.24에서 제거됨. 현재 클러스터는 1.34이므로 `--bind-address`로 변경 필요.
- **적용**: ansible playbook 실행으로 기존 클러스터에 반영 완료

#### 2. kube-proxy (`metricsBindAddress`)

- **파일**: `kubernetes/roles/config-kube-proxy/tasks/main.yaml`
- **변경**: `metricsBindAddress: ""` → `metricsBindAddress: "0.0.0.0:10249"` replace 태스크 추가
- **적용**: 기존 클러스터는 수동으로 ConfigMap 수정 + rollout restart 완료

#### 3. etcd (`--listen-metrics-urls`)

- **파일**: `kubernetes/roles/kubeadm-init-prep/templates/kubeadm-config.yaml`
  - `etcd.local.extraArgs`에 `listen-metrics-urls: "http://0.0.0.0:2381"` 추가 (신규 구축용)
- **파일**: `kubernetes/roles/etcd-ha/templates/etcd.service` (레거시)
  - `--listen-metrics-urls=http://0.0.0.0:2381` 추가
- **적용**: 기존 클러스터는 ansible ad-hoc으로 `/etc/kubernetes/manifests/etcd.yaml` 직접 수정 완료

#### 4. UFW 방화벽 포트 업데이트

- **파일**: `kubernetes/roles/ufw/tasks/main.yaml`
- **변경**:
  - kube-scheduler: `10251` → `10259` (secure 포트, 1.24+ 대응)
  - kube-controller-manager: `10252` → `10257` (secure 포트, 1.24+ 대응)
  - etcd: `2379:2380` → `2379:2381` (메트릭 포트 2381 포함)
  - kube-proxy: `10249/tcp` 추가 (신규)
- **적용**: ansible playbook + 수동 `ufw allow` 실행으로 기존 클러스터에 반영 완료

### 결과

Prometheus에서 kube-proxy, kube-controller-manager, kube-scheduler, etcd 메트릭 스크래핑 정상 확인. 관련 알럿 모두 해소됨.
