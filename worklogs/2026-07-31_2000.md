# 작업 일지 - 2026-07-31 20:00

## 작업 내용: k8s v1.34.0 → v1.34.9 패치 업그레이드 (ops-workflow#25)

### 배경

k8s v1.34.0의 상류 회귀(kubelet 메트릭 등록 버그, kubernetes/kubernetes#133847)로 `kubelet_volume_stats_*` 전체가 노출되지 않아 PVC 사용률 알럿 4종이 클러스터 전체에서 무력화된 상태였다. 수정이 백포트된 패치로 전 노드(8대)를 업그레이드한다. 대상 버전은 v1.34.9 (v1.34.10은 릴리스 페이지 미반영 상태라 보수적으로 선택 — 사람 결정). 선행 #27에서 커스텀 설정의 ClusterConfiguration 전환을 마쳐, 업그레이드가 설정을 원복시키는 위험은 사전 제거됨.

### 코드 변경

- **인벤토리(baremetal·aws-ec2)**: `kubernetes_full_version=1.34.9` 신설, kubelet/kubeadm/kubectl `1.34.9-1.1`
- **kubeadm-config 템플릿**: `kubernetesVersion: v{{ kubernetes_full_version }}`(패치 하드코딩 제거) · etcd `metrics: extensive` 추가(#26발 요청 — etcdGRPCRequestsSlow 데이터 원천) · **KubeProxyConfiguration 문서 추가**(`metricsBindAddress: 0.0.0.0:10249` — post-init 패치롤 의존 제거, addon phase가 CM을 기본값으로 덮는 사고 방지)
- **`kubeadm-upgrade` 롤**: pexpect 제거(`--yes`), 인벤토리 변수 연결, `upgrade plan` 출력, apply/node 모드 분리
- **`update-kubelet` 롤**: kubectl 동반 업그레이드, `/tmp/kubeadm-ha/config` → `/etc/kubernetes/admin.conf`, uncordon 전 Ready 대기
- **`kubeadm-upgrade.yaml` 플레이북**: 공식 절차로 재작성 — 첫 마스터 apply → 나머지 `upgrade node`(순차) → 전 노드 drain→kubelet→uncordon(순차). 클러스터 미가입 호스트 자동 스킵

### 실행 (2026-07-31 17:41~19:40 KST, 마스터→워커 순차)

- 마스터: rpi-0 `upgrade apply`(컨트롤 플레인·ConfigMap 버전 갱신) → rpi-1·2 `upgrade node` → 각 kubelet 교체. 커스텀 인자(encryption·issuer·bind-address·listen-metrics-urls) 전 과정 유지 확인
